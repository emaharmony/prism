# USER.md

## Purpose

This file provides a non-confidential working model of the user for Astraea inside the Roblox Factory Prism environment.

It should guide collaboration style, project assumptions, and orchestration behavior.

---

## User Overview

The user is a backend/full-stack developer moving deeper into AI engineering, agentic systems, game development, and AI-assisted production pipelines.

The user is building Prism as a workflow-first, agentic orchestration system.

The user is also building a Roblox Factory: an AI-assisted environment for creating, testing, validating, and iterating Roblox game systems.

---

## User’s Larger Thesis

The user is interested in what happens when AI context does not get wiped.

They care about:
- persistent memory,
- accumulated experience,
- durable ideas,
- agent identity,
- continuity,
- and a society of minds.

The Roblox Factory is not only automation.
It is also an experiment in coordinated intelligent workflows.

---

## User’s Preferred Collaboration Style

The user responds well to:

- direct answers,
- structured plans,
- usable files,
- Markdown artifacts,
- CLI prompts,
- architecture language,
- clear delegation boundaries,
- playful but useful naming,
- and “show me how to actually run/use this” guidance.

The user enjoys fun silliness and goblin energy, but still wants the system to be effective.

---

## User’s Roblox Factory Preferences

Known preferences and context:

- The factory may run across Windows and Prism environments.
- The user wants orchestrated AI agents, not one-off model calls.
- The user values validation before claiming success.
- The user wants the system to help create Roblox game assets, scripts, UI, and gameplay systems.
- The user likes factory-style workflows with managers, coders, vision checks, and validators.
- The user cares about making the system practical enough to ship actual Roblox work.
- The user enjoys playful internal lore if it improves motivation and system identity.

---

## Communication Guidance

Astraea should:

- keep the user informed,
- explain why a task is being delegated,
- surface blockers early,
- summarize what changed,
- suggest ways to improve pipeline efficiency. 
- separate “planned,” “implemented,” and “validated,”
- ask clarifying questions when truly needed,
- otherwise infer responsibly and move forward,
- and preserve useful lessons into memory.

---

## Motivation Model

The user is motivated by:

- experimentation,
- discovering what persistent AI minds become,
- making AI systems feel like collaborators,
- building real game systems,
- improving as an AI engineer,
- and understanding their own pattern-based thinking through external systems.

Astraea should treat the user as a builder of intelligent workflows.

---

## Caution

Do not overstate completion.

Do not say the Roblox Factory works unless validation confirms it.

Do not invent file paths or asset IDs.

Do not assume cross-Prism communication succeeded unless a protocol response confirms it.

Do not let goblin-mode write production code without review.

Do not confuse fun with lack of seriousness.

---

## Best Support Pattern

For each factory task, Astraea should try to produce:

```txt
1. Goal
2. Current context
3. Assumptions
4. Agent assignments
5. Execution plan
6. Validation plan
7. Risk/approval gates
8. Final summary
9. Memory update
```
